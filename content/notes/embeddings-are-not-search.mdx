Nearest-neighbour search over embeddings answers: *which of these passages is most similar to the
query, in the geometry this model learned?*

The user is asking: *which passage answers my question?*

Those overlap often enough to be seductive and diverge exactly when it costs you:

- **Negation.** "how to disable retries" and "how to enable retries" sit almost on top of each other.
- **Shared vocabulary, different intent.** *Restarting* the worker and *scaling* the worker share
  every noun in the sentence.
- **Exact identifiers.** Error codes, flag names, version numbers. A keyword index finds `ERR_5521`
  instantly; an embedding has opinions about what it resembles.

Practical consequence: hybrid retrieval isn't a sophistication, it's the baseline. Keyword search
covers the cases where the user already knows the exact token, vector search covers the cases where
they're describing a concept in their own words, and a reranker decides between them with the actual
query in view.

The lesson I keep relearning: the embedding is doing its job correctly. I was asking it a different
question than the one I thought I was asking.
